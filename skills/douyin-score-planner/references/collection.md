# 已授权宿主只读取数

第一版实测路径为 macOS 原生抖店工作台（com.temai.im）＋宿主 cua_repl。Windows、Chrome 完整导出尚未实测；不能因有 Chrome 就报告自动取数 ready。

## 能力检查
从宿主当前工具清单确认 CUA 可用，按其首次调用规则取得用户指定应用或浏览器，先读工具文档。实际打开正确页面并观察店铺名称和登录状态。Shell doctor 不会验证这些，只会返回 requires_host_probe。缺少 CUA 时引导接入宿主官方提供的能力；没有可公开、已验证的安装地址时不要编造“下载此扩展”。

用户明确选择原生抖店时，可取得 com.temai.im。Chrome 只能使用扩展通道；必须遵守 SKILL.md 的超时恢复规则。工具策略拒绝不得换通道规避。不可读取应用缓存、数据库、cookie或通过私有HTTP端点取数。

## 原生流程
1. 观察首页确认店铺名称，保存私有核对记录。进入商家体验分，核对行业、更新时间、总分、分项权重、加减分。只用当前观察到的入口；不要复制别人的元素序号或坐标。
2. 将 scripts/cua-collector.js 中的函数定义送入已授权 cua_repl（按宿主支持的代码加载方式；不要求终端 Node）。执行 collectScoreSnapshot(app)。脚本每次取得完整最新AX树后精确匹配白名单按钮，歧义即停止。
3. 历史图只有均值和图点时，图点数可作为需注明的有效天数假设，绝不能视觉填造每日精确分。不能导出历史日分就保留缺项。
4. 每个报表导出前，在本地运行 `<技能Python> scripts/collect.py baseline --directory <下载目录> --out <私有目录/本次基线.json>`。
5. 在概览页执行 requestScoreExport(app,'reviews',true)（quality/service同理）。true只在本次已观察确认店铺身份后传入。脚本核对指标及非空查询结果才允许请求一次导出。空表不等于故障，不盲目重试；先核对。
6. 观察下载任务结果。遇到原生保存窗口，可执行 saveScoreDownload(app,'含日期和批次的唯一文件名.xlsx')。只写本地新文件，不替换已有文件。网页下载没有原生窗口时不调用此函数。
7. 运行 `collect.py finish --baseline <基线> --kind reviews --shop-key <店铺标识> --destination <私有归档目录> --expected-rows <后台数量> --receipt <私有回执.json>`。此步骤确认新文件出现、稳定、可读、字段匹配、行数相符、哈希，并保留原件。没有回执不报“导出完成”。
8. 用最新AX中已观察的“商家体验分”面包屑返回概览（scoreAction(app,'back')），逐项导出；发生登录/权限/页面变化时停止当前步骤并报告具体缺项。

脚本的按钮白名单是实现约束，不是平台技术权限隔离。宿主agent仍必须遵守用户只读边界。可能出现分页、日期筛选、导出下载中心或浏览器保存差异，由agent依据当前观察完成已授权的查询/下载；禁止凭猜测提交动作。

## 私有数据与成功判定
原始报表、下载清单、店铺身份、页面快照、截图、目标及分析报告均存放在项目外的用户私有目录。每批记录来源、更新时间、窗口、行数和哈希。保存文件只能证明本地下载，不证明所有需要的数据都齐全。自动取数报告必须分列：已读取快照、已完成导出、仍缺资料。
